# 架构与后续开发顺序

技术栈遵循课题：用户端Uni-app（微信小程序/H5）；管理端Vue 3 + Element Plus；后端Spring Boot + MyBatis-Plus；MySQL 8.0 + Redis。建议后端采用JDK 17兼容的Spring Boot版本，真正初始化工程时再核实所用版本与依赖兼容性。当前未创建pom.xml、package.json或假启动入口。

项目根目录统一保存全部系统源代码与设计资料。后端按auth、catalog、cinema、screening、booking、payment、ticket、afterSale、member、marketing、moderation、statistics、audit拆业务包，共享数据库但仅经服务接口交互。admin-web内区分platform和cinema路由区域；如学校要求两个独立Web包，可在此根目录下拆为admin-platform-web与admin-cinema-web，不影响数据模型。

1. 数据库与基础配置：导入脚本、引入迁移工具、配置环境变量、开发/测试库隔离。
2. 账号与权限：注册登录、管理员初始化、角色菜单、影院授权校验、审计。
3. 影片与影院：分类、资料、影院申请、影院管理员申请及审核。
4. 排片与座位：布局、排片冲突保护、票价策略、场次库存快照。
5. 售票闭环：移动端选择影片、影院、场次和座位；锁座、下单、MOCK沙箱支付、电子票、超时释放、扫码核销。
6. 退票改签：部分退票、审核、异步退款、同院改签补款/退差与失败补偿。
7. 会员营销与互动：积分、会员价、券、公告、活动、评价、反馈、敏感词。
8. 数据看板与交付：实时统计、定时汇总、集成测试、三端联调、部署和毕业论文材料。

售票模块必须做真正的多请求并发和跨事务集成测试。真实微信支付需商户资质、支付回调域名和渠道配置；毕业设计可先完成明确标记的MOCK支付，不能将模拟成功页面描述成已接通真实支付。

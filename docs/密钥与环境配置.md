# 密钥与环境配置

## 存放与提交规则

真实配置放在被忽略的.env.local、各端.env.local、backend/src/main/resources/application-local.yml或.secrets目录中。仓库只保存空值的.env.example，以及使用环境变量占位符的非敏感配置。不要把密钥写入Java、Vue、TypeScript、Uni-app的manifest.json、SQL初始化数据、注释、截图或日志；.gitignore不会识别普通源代码中的密钥。

根目录.env.example列出未来后端与前端配置所需的变量名称，凭证项均为空。它是配置参考，不代表当前系统已经实现了加载器。Spring Boot不会自动加载根目录.env文件：实际开发时通过启动进程、IDE运行配置或部署系统注入环境变量，或使用被忽略的application-local.yml。Vite只会按对应工程的环境目录加载.env文件，不会自动共享其他工程的配置。

本次扩展了Git忽略规则：所有层级的.env与.env.*（仅放行.env.example）、本地Spring Boot配置、私密配置目录、SSH私钥、PEM/KEY文件、证书密钥库及常见服务账号凭据文件。代码、数据库SQL、普通application.yml及空配置模板继续正常提交。构建输出和日志也不提交。

## 地图API

服务端地图Web服务Key、签名密钥和其他必须保密的凭证只保留在后端环境中，例如MAP_SERVER_API_KEY。前端需要相关功能时调用受身份校验、参数校验和限流保护的后端接口，不能提供允许用户任意转发请求的开放代理。

浏览器JavaScript地图SDK或小程序SDK需要客户端Key时，应为它申请独立的客户端Key，按照地图提供商要求配置域名、应用标识/包名/签名等限制，并设置合理配额。此类客户端Key会出现在运行的应用中，不能承诺绝对保密，也不能与服务端密钥混用。具体限制以最终选择的地图服务商控制台为准。

VITE_前缀的环境变量会进入前端构建产物，即使.env.local未被Git跟踪也一样。因此VITE_MAP_BROWSER_KEY只能填允许在客户端使用并已配置限制的Key，绝不能填后端Web服务Key、支付密钥或JWT签名密钥。Uni-app客户端或小程序包内的配置也应按用户可见处理。[Vite官方说明](https://vite.dev/guide/env-and-mode)

## 已提交内容与误泄露

.gitignore只影响未跟踪文件，不会使已提交文件退出版本管理，也不会清除历史。后续每次提交前检查git status和暂存差异，确认真实配置没有进入提交；不要使用git add -f强制加入秘密文件。[Git官方说明](https://git-scm.com/docs/gitignore)

若真实凭证已经上传，应立即在服务商处撤销或轮换，随后再处理当前文件、Git历史、日志和构建产物。仅删除当前文件或补一条忽略规则，不能让已公开的密钥恢复安全。请勿把真实密钥发在聊天中。

本次检查的已跟踪文件列表中没有.env真实配置、SSH私钥或证书密钥文件；这不是对未来所有提交的自动保密保证。
